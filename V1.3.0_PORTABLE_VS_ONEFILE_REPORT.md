# v1.3.0 Portable vs Onefile

| Concern | Portable/onedir | Onefile |
|---|---|---|
| Startup | Direct launch after extraction | Extracts to a temporary location first |
| Troubleshooting | Files and bundled Graphviz are directly inspectable | Runtime is less directly inspectable |
| Updates | Replace the extracted version atomically | Replace the single verified executable |
| Graphviz | Stable adjacent bundled layout | Runtime locates Graphviz inside the temporary bundle |
| Closed networks | Well suited | Well suited after package/hash transfer |
| License payload | Visible at bundle root and in `licenses/` | Embedded by PyInstaller, correlated to the build inventory, and delivered with accessible release policy files |

Both formats run the same analyzer and are smoke-tested with Nmap, Nmap+Zeek,
SVG, PNG, output rename/delete/reuse, and logging lifecycle checks. Exact sizes
and measured package results belong in `V1.3.0_LINUX_PACKAGING_REPORT.md` after
the final workflow artifacts are downloaded and hashed. Licensed Ubuntu run
30718727917 and Rocky run 30718727899 passed their portable, onefile, native
attribution, license-payload, and smoke-test gates at commit `4710008`.

Release builds use `requirements-build.lock`. Both formats are rebuilt from the
same commit; the onefile extraction inventory and the portable native inventory
must contain no unattributed ELF files before artifacts are uploaded.
